# CHQ Calendar iOS App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Native SwiftUI iOS app (`ios/`) with feature parity to chqcal.org's read-only calendar: instant cached launch, one-touch filters, week/theme selection, article links, favorites, add-to-calendar.

**Architecture:** Single app target + unit-test target in a hand-authored Xcode 16-format project (synchronized folders). `@Observable` app model on the MainActor; `actor EventRepository` does stale-while-revalidate over a generic disk cache with ETag revalidation; pure-function domain layer (season weeks, filter pipeline) ported from the web app and unit-tested with Swift Testing.

**Tech Stack:** Swift 6 (Xcode 26, `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`), SwiftUI, Observation, URLSession, EventKitUI, Swift Testing. Zero third-party dependencies.

**Spec:** `docs/superpowers/specs/2026-07-31-ios-app-design.md` — read it first; §4 is the verified data contract.

## Global Constraints

- Deployment target **iOS 18.0** (raised from 17.0 during the 2026-08-01 iOS UX filtering plan's Task 7 fix round, to use `onScrollGeometryChange`); `TARGETED_DEVICE_FAMILY = 1,2`; Swift 6 language mode; no packages/dependencies.
- All date parsing/grouping pinned to **America/New_York** via `ChqTime` — never `TimeZone.current` in domain code.
- Event TTL **3600 s**; user-state expiry **30 days**; sidecar fetch timeout **3 s**, failures non-fatal.
- Base URL `https://www.chqcal.org`. Endpoints exactly as spec §4.
- Test/build command (run from `ios/`):
  `xcodebuild test -project ChqCalendar.xcodeproj -scheme ChqCalendar -destination 'platform=iOS Simulator,name=iPhone 17,OS=26.1' CODE_SIGNING_ALLOWED=NO -quiet`
- Commit after every task to branch `feature/ios-app`. NEVER commit to `main`. Frontend/backend untouched.
- Unit tests use **Swift Testing** (`import Testing`, `@Test`, `#expect`). Fixtures load via `Bundle(for: FixtureToken.self)`.

### Task 2: Time helpers, HTML entities, models + decoding

**Files:**

- Create: `ios/ChqCalendar/Models/Event.swift`, `ios/ChqCalendar/Models/Sidecars.swift`

**Interfaces:**
- Produces:
  - `enum ChqTime { static let zone: TimeZone; static var calendar: Calendar; static func parse(_ s: String) -> Date?; static func dayKey(for date: Date) -> String; static func dayTitle(for date: Date) -> String; static func timeString(for date: Date) -> String; static func endOfDay(_ date: Date) -> Date }` — all NY-pinned. `parse` accepts `"yyyy-MM-dd HH:mm:ss"` AND `"yyyy-MM-dd'T'HH:mm:ss"`.
  - `extension String { var decodingHTMLEntities: String }` — handles `&amp; &#038; &#8217; &quot; &#039; &lt; &gt; &nbsp;` and numeric `&#NNNN;` generally.
  - `struct Event: Identifiable, Hashable, Sendable` fields: `id, title: String; start, end: Date; details: String?; displayLocation: String?; venueAddress: String?; categoryNames: [String]; tags: [String]; presenter: String?; cost: String?; pageURL: URL?; imageURL: URL?; status: EventStatus; week: Int?; filterTokens: Set<String>` (lowercased tags + categoryNames). Custom `init(from decoder:)` per spec §4: `displayLocation = venue.name ?? location` (entity-decoded); `categoryNames` = union of `categories[].name` + `category`, entity-decoded, deduped, order-preserving; `imageURL = image.sizes["large"]?.url ?? image.url`; `status` maps `"cancelled"→.cancelled, "rescheduled"→.rescheduled`, anything else → `.scheduled`; throws only if `id/title/startDate` missing or unparseable.
  - `enum EventStatus: Sendable { case scheduled, cancelled, rescheduled }`
